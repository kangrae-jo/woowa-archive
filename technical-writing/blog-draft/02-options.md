# ② 비교한 방법: 어떤 방법들을 봤나요?

작성 상태: 본문 작성 대기 중입니다. 작성 범위는 [문서 작성 계획서](../WRITING_PLAN.md)를 따릅니다.

## 본문에서 설명할 질문

- `@Async`, Worker 직접 HTTP 호출, DB Job Queue, 메시지 브로커는 작업 보존·등록 원자성·운영 비용에서 어떤 차이가 있나요?
- 당시 통신 제약과 생성 시간의 불확실성이 선택에 어떤 영향을 주었나요?
- 도메인 데이터와 Job을 같은 DB에 저장하는 조건에서 DB Job Queue를 선택한 이유와 비용은 무엇인가요?

## 작성 전 확인할 근거

당시 직접 통신이 불가능했던 구체적인 이유는 확인이 필요합니다. 직접 HTTP 호출 대안의 호출 방향과 결과 전달 방식을 정의한 뒤 비교표를 작성합니다. 당시 제약과 현재 구현의 선택은 구분해 설명합니다.

참조: [작성 계획서](../WRITING_PLAN.md), [현재 프로세스와 DB 경계](../README.md).
